## 3. Rollback Strategy

| Escenario | Cuándo | Acción | Pérdida de datos |
|-----------|--------|--------|-----------------|
| **Pre-cutover** (Phase 1–4) | Antes de apagar OLD app | `DROP TABLE UsuarioTenant` + `ALTER TABLE Accesos DROP COLUMN IdUsuarioTenant` + recrear índices legacy + restaurar triggers + restaurar SPs | Ninguna |
| **Post-cutover** (Phase 6–8) | Después de que NEW app recibe tráfico | `BACKUP` pre-cutover + restore completo + restaurar OLD SPs + OLD app | Transacciones post-cutover (aceptado) |
| **Contract** (Phase 8C) | Después de eliminar legacy columns | Restore desde backup pre-Contract | Transacciones post-Contract (aceptado) |
| **A1.1 individual** (schema) | Error en preflight | No ejecutar. Arreglar datos, re-ejecutar preflight | Ninguna |
| **A1.2 individual** (migración) | Error en validación post-migración | Rollback a backup pre-migración + re-ejecutar con datos corregidos | Ninguna |
