## 2. Bugs

### BUG-001 — CLOSED
- **Area**: Authentication / Repository
- **Severity**: Alta
- **Cause**: `ObtenerUsuarioPorNomAsync` in `AuthRepository.cs` not projecting `IdEstado` in SELECT
- **Impact**: Platform login (`POST /api/auth/login/platform`) always returned `CUENTA_INACTIVA` because `PlatformLoginAsync` received default int 0 instead of actual user state
- **Fix**: Added `IdEstado = u.IdEstado` to SELECT projection
- **Validation**: Platform login PASS, Platform JWT has null TenantId/UsuarioTenantId, 66/66 regression PASS, 12/12 A1.8 core PASS
- **Status**: 🔒 CLOSED

### LEAK-001 — CROSS-TENANT DATA LEAKAGE — OPEN
- **Area**: WebAPI / Controllers / UsuariosController
- **Severity**: Alta
- **Cause**: `GET /api/usuarios/{id}` and `GET /api/usuarios` (unscoped) do not validate tenant membership
- **Impact**: A tenant-scoped JWT (e.g., TenantId=3) can read any user's data from another tenant via direct ID access
- **Evidence**:
  - T3 JWT → `GET /api/usuarios/5` (admin_vestuario, tenant 4) → returns full user data
  - T3 JWT → `GET /api/usuarios` → returns all 12 users across tenants 1, 3, 4
- **Fix needed**: Add UsuarioTenant membership check in `GetById`; scope `GetAll` by tenant context

## 5. Findings

### Blocking for A1.8 FINAL

**LEAK-001: Cross-tenant data leakage via unscoped endpoints**
- **Endpoints affected**: `GET /api/usuarios`, `GET /api/usuarios/{id}`
- **Root cause**: These endpoints do not validate UsuarioTenant membership
- **Severity**: Alta — PII leak across tenants
- **Suggested fix**:
  1. `GetById(int id)`: Before returning data, verify the requesting user has an active UsuarioTenant membership for the target user's tenant (or the user belongs to the caller's tenant scope)
  2. `GetAll()`: Filter by `_tenantContext.CurrentId` or remove the unscoped method

### Non-blocking (Info/Watch)

1. **Permissions identical across tenants**: Test user `test_multitenant` has the same `permiso[]` in both T3 and T4. This is expected because the user has the same ADMIN role in both tenants. In production, different roles per tenant would produce different permission sets.
2. **Unscoped GET /api/usuarios**: Used by system users with `is_system=true` flag. For non-system users with `USUARIOS_VER`, this returns cross-tenant data. Consider adding tenant check.
