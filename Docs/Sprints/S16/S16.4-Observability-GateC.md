## 6. Correlación

Para el flujo HTTP:

Login → MFA → JWT → Cache → Email → Logout

se debe verificar:

```text
correlationId(Login)
        ↓
correlationId(Cache)
        ↓
correlationId(Email)
        ↓
correlationId(Logout)
```

La correlación debe mantenerse consistente cuando el flujo se ejecuta dentro
del mismo contexto HTTP.

Los Background Jobs no requieren `correlationId` HTTP porque no disponen de
`HttpContext`.

## 8. Bloqueadores conocidos

- **`accesos/asignar`** — error preexistente de concurrencia
  (`expected 1 row, got 0`). No pertenece al alcance funcional de S16.4.
- **`Password_Reset`** — la instrumentación está implementada en el punto

  recuperación/restablecimiento de contraseña y disponer del mecanismo de
  entrega correspondiente.
- **Framework CBP** — `Jwt_Validated` y `Event_*` permanecen pendientes de
  instrumentación en el framework por pertenecer al punto semántico real de
  ejecución.

### Hallazgos de contrato de esta corrida (2026-08-08 01:30) — RESUELTOS 2026-08-08 02:24

1. **`Login_Succeeded` / `Login_Failed` no emitidos por la ruta probada.**
   El Gate C E2E usa `POST /api/auth/login/platform` (`PlatformLoginAsync`).
   Esa ruta emitía `Jwt_Generated` + mensajes legacy pero **NO**
   `Login_Succeeded` ni `Login_Failed`. **RESUELTO**: `PlatformLoginAsync`
   ahora emite `Login_Succeeded` (éxito) y `Login_Failed` (5 ramas de rechazo:
   usuario no encontrado, cuenta eliminada, cuenta inactiva, hash no disponible,
   contraseña inválida) — verificada en corrida fix 02:24 (C1.1/C1.4 3/3 PASS).

2. **`Email_Queued` con `correlationId=null` dentro de request HTTP.**
   El evento `Email_Queued` emitido durante `POST /api/apps` llevaba
   `correlationId=null` pese a estar en un request HTTP con correlation activo.
   **RESUELTO**: `EmailQueue.EnqueueAsync` resuelve fallback
   `job.CorrelationId ?? HttpContext.Items[HttpCorrelationIdKey]` — verificada
   en corrida fix 02:24 (C3.1): `Email_Queued` comparte `correlationId` W3C
   (`00-fe395...`) con `AUTHZ OK`, `Cache_Invalidation` y `RequestLoggingMiddleware`
   del mismo request. Solo `Email_Sent` en background tiene null legítimo
   (sin HttpContext). Check #13 cumplido.
