## 3. GetRepository<TEntity>() — decisión estricta

**Decisión**: REMOVE del contrato, sin reemplazo.

**Justificación**: el Discovery demuestra `uso externo = 0`. Esto justifica retirarlo del contrato, **pero no justifica** introducir un mecanismo alternativo (extension method) que no responde a ningún requerimiento funcional.

**Ejecución (S25.2, futura)**:
1. Retirar `GetRepository<TEntity>` de `IUnitOfWorkAsync` / `IUnitOfWorkSync`.
2. La implementación interna puede conservarse temporalmente.
3. Tras la eliminación del contrato, realizar una búsqueda de compilación/referencias para determinar si la implementación interna sigue siendo necesaria.
4. Si tampoco tiene utilidad interna real, se elimina en la implementación.

**Principio aplicado**: mínimo cambio.

## 4. Detach<TEntity>() — inconsistencia de paridad

**Texto oficial (hallazgo, no decisión final)**:

> `Detach<TEntity>` — miembro no utilizado externamente y presente únicamente en Sync; inconsistencia de paridad detectada. Su eliminación o incorporación de contraparte Async queda diferida a un análisis específico.

**Reglas**:
- NO agregar `DetachAsync` automáticamente para fabricar simetría.
- NO eliminar la versión Sync todavía.
- Queda como candidato de análisis futuro.

**Regla de paridad evocada**: paridad **funcional**, no "cada método debe tener un clon con Async".

## 5. Contrato objetivo (Opción F)

### 5.1 `CBP.Data.Abstractions` (contrato agnóstico)

`IUnitOfWorkAsync` / `IUnitOfWorkSync` **no genéricos**, sin `DbContext`, sin EF.

Miembros conservados en el contrato:

| Miembro | Justificación |
|---------|---------------|
| `SaveChangesAsync` / `SaveChanges` | 124 usos |
| `SaveEntitiesAsync` / `SaveEntities` | Familia SaveChanges |
| `RawQuery` | 12 usos — acceso a SPs |
| `ExecuteInTransactionAsync` / `ExecuteInTransaction` | 1 uso (`DispConfiablesController.cs:88`) |

**Eliminados del contrato**: `DbContext`, `BeginTransaction`, `CommitTransaction`, `RollbackTransaction`, `HasChanges`, `RejectChanges`, `GetCustomRepository`, `GetRepository<TEntity>`.

**No añadidos**: `Detach` (pendiente análisis), extension method de `GetRepository` (no creado).

### 5.2 `CBP.Data.Asynchronous` (implementación EF genérica)

```csharp
public class UnitOfWorkAsync<TDbContext> : IUnitOfWorkAsync, IDisposable
    where TDbContext : DbContext
```

- Constraint EF conservada **en la implementación**.
- `BeginTransactionAsync` / `CommitTransactionAsync` / `RollbackTransactionAsync` pasan a **privados** de la implementación (usados internamente por `ExecuteInTransactionAsync`).
- `DbContext` propiedad se mantiene solo a nivel de implementación si es necesario internamente; no se expone.

### 5.3 `CBP.Data.Synchronous` (equivalente sync)

```csharp
public class UnitOfWorkSync<TDbContext> : IUnitOfWorkSync, IDisposable
    where TDbContext : DbContext
```

Misma estructura. Paridad funcional obligatoria.

### 5.4 Repositorios

`IRepositoryAsync<TEntity>` / `IRepositorySync<TEntity>` **sin cambios**: su superficie (`Expression<>`, `IQueryable`, `Result<T>`) ya es BCL-agnóstica o propia. No participan de F1.

### 5.5 DI (registro de extensión)

```csharp
public static IServiceCollection AddUnitOfWorkAsync<TDbContext>(this IServiceCollection services)
    where TDbContext : DbContext
{
    services.AddScoped(typeof(IUnitOfWorkAsync), typeof(UnitOfWorkAsync<TDbContext>));
    return services;
}
```

Equivalente Sync. Los consumidores inyectan el contrato `IUnitOfWorkAsync`; el genérico queda confinado al registro en `Program.cs` (y al único `GetRequiredService` de `IdenExtTokensRotacionJob.cs:119`).
