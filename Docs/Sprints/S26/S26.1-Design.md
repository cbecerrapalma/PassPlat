## 1. Conclusión del Discovery (S26.0)

- **5 consultas EF directas** en 2 servicios (`FederacionService`, `OAuthCatalogValidationService`), todas read-only con `AsNoTracking`.
- **4 repos existentes** cubren el aggregate/catálogo: `IIdenExtRepository`, `IProvIdenRepository`, `IConfProvIdenRepository`, `IAudIdenExtRepository`.
- **3 métodos nuevos** — no se crean repositorios nuevos.
- La frontera objetivo se mantiene:
  ```
  PassPlat.Aplicacion
        ↓
  Repositorios / contratos
        ↓
  PassPlat.Datos
        ↓
  EF Core
  ```

## 2. Decisiones cerradas

### DEC-1 — F-1 (GroupBy de IdenExt): read model agnóstico en Datos, proyección en Aplicación

**El repositorio NO devuelve ni conoce `ProveedorEstadisticasDto`** (invertiría la dependencia).

```
IIdenExtRepository (Datos)
      ↓
DesgloseProveedorReadModel  ← estructura propia de Datos (sin refs a Aplicación)
      ↓
FederacionService
      ↓
ProveedorEstadisticasDto  ← DTO de Aplicación
```

- El read model vive en `PassPlat.Datos\Models\DesgloseProveedorReadModel.cs`:
  ```csharp
  public class DesgloseProveedorReadModel
  {
      public int IdProvIden { get; init; }
      public string Codigo { get; init; } = string.Empty;
      public string Nombre { get; init; } = string.Empty;
      public string? Icono { get; init; }
      public int TotalVinculadas { get; init; }
  }
  ```
- Justificación: el read model es una estructura plana de proyección SQL (GroupBy + Count), sin lógica de dominio ni referencia a `PassPlat.Aplicacion.Dtos`. Respeta el grafo Datos → Dominio (no Datos → Aplicación).
- **Alternativa rechazada**: devolver `IReadOnlyList<IdenExt>` y agrupar en memoria en Aplicación. Inviable: materializaría entidades completas incluyendo `AccessToken`, `RefreshToken`, `IdToken` (byte[] sensibles) solo para contar — fuga de datos y rendimiento.
- El método del repo hace `GroupBy(i => new { i.IdProvIden, i.ProvIden!.Codigo, i.ProvIden.Nombre, i.ProvIden.Icono }).Select(...)` en SQL (EF permitido en Datos), preservando el orden actual implícito.

### DEC-2 — F-3 (últimas 10 AudIdenExt): reutilizar `ObtenerPorTenantAsync` — Include necesario

**El `Include(a => a.ProvIden)` del método existente ES necesario** para poblar la navegación `ProvIden` que la proyección `UltimaActividadFederacionDto` consume (`ProveedorNombre`/`ProveedorCodigo`).

- `IAudIdenExtRepository.ObtenerPorTenantAsync(idTenant, limite)` ya filtra por `IdTenant`, ordena `FecEvento` desc, `Take(limite)`, `AsNoTracking()`, con `Include(ProvIden)`. Con `limite = 10` es **funcionalmente idéntico** a la consulta original.
- **No se introduce método de proyección directa nuevo**: la proyección a `UltimaActividadFederacionDto` se hace en el servicio (también evita un 4º método). Costo del Include limitado a 10 filas AsNoTracking — despreciable.
- Verificado: `AplicacionProfile` (L327-328) ya mapea `AudIdenExt → AudIdenExtResumenDto` consumiendo `ProvIdenNombre` — patrón coherente; en este caso el servicio proyecta manualmente los 7 campos ligero del DTO.

### DEC-3 — `IgnoreQueryFilters()`: limpieza menor dentro del mismo método F-1

- Verificado vía grep: **no existe `HasQueryFilter`** en `PassPlat.Datos\Configurations`. El `.IgnoreQueryFilters()` de `FederacionService` L28 es **no-op**.
- Se omite en el nuevo método del repo **únicamente porque es parte del mismo método que se refactoriza** (F-1). **No se justifica** un cambio independiente solo para quitar una línea.
- Riesgo documentado: si en el futuro se agrega un query filter global de soft-delete, F-1 deberá respetarlo (mismo comportamiento que el resto del sistema).

### DEC-4 — O-1 (ProvIden ordenados): reutilización directa

- `IProvIdenRepository.ObtenerTodosOrdenadosAsync()` coincide **exactamente** con la consulta de OAuth (`OrderBy Orden + AsNoTracking`). Sin cambios.

### DEC-5 — O-2 (ConfProvIden todos): método nuevo `ObtenerTodosAsync`

- `IConfProvIdenRepository` no expone "todos sin filtro". Nuevo método en el repo existente:
  ```csharp
  Task<Result<IReadOnlyList<ConfProvIden>>> ObtenerTodosAsync(CancellationToken ct = default);
  ```
  - `DbSet.AsNoTracking().ToListAsync(ct)` — sin tenant, sin Includes (la validación solo lee `ResponseType`/`GrantType`).
  - Alineado con `ObtenerTodosOrdenadosAsync` de ProvIden (mismo patrón).

## 4. Signature de los 3 métodos nuevos

### `IIdenExtRepository` (F-1)
```csharp
Task<Result<IReadOnlyList<DesgloseProveedorReadModel>>> ObtenerDesglosePorProveedorAsync(
    int idTenant, CancellationToken ct = default);
```
- Impl: `DbSet.Where(i => i.IdTenant == idTenant && !i.Eliminado).GroupBy(i => new { i.IdProvIden, i.ProvIden!.Codigo, i.ProvIden.Nombre, i.ProvIden.Icono }).Select(g => new DesgloseProveedorReadModel { ... TotalVinculadas = g.Count() }).AsNoTracking().ToListAsync(ct)`.
- `using PassPlat.Datos.Models;` (ya presente en el repo).
- Resultado envuelto en try-catch con `Result.Failure("DB_ERROR", ex.Message)` (PATRÓN AGENTS.md repositorios).

### `IProvIdenRepository` (F-2)
```csharp
Task<Result<int>> ContarActivosAsync(CancellationToken ct = default);
```
- Impl: `await DbSet.CountAsync(p => p.Activo, ct)`.
- Sin `AsNoTracking` necesario (Count no materializa entidades).

### `IConfProvIdenRepository` (O-2)
```csharp
Task<Result<IReadOnlyList<ConfProvIden>>> ObtenerTodosAsync(CancellationToken ct = default);
```
- Impl: `DbSet.AsNoTracking().ToListAsync(ct)`.

## 5. Cambios en servicios (constructores DI)

### `FederacionService`
```csharp
public FederacionService(
    IIdenExtRepository idenExtRepo,
    IProvIdenRepository provIdenRepo,
    IAudIdenExtRepository audIdenExtRepo)
```
- Elimina `PassPlatDbContext`, elimina `using Microsoft.EntityFrameworkCore`.
- `desglose`: `repo.ObtenerDesglosePorProveedorAsync(idTenant)` → mapea `DesgloseProveedorReadModel → ProveedorEstadisticasDto`.
- `totalProveedores`: `repo.ContarActivosAsync()`.
- `ultimasActividades`: `repo.ObtenerPorTenantAsync(idTenant, 10)` → proyecta a `UltimaActividadFederacionDto` (con `a.ProvIden?.Nombre/Codigo`).

### `OAuthCatalogValidationService`
```csharp
public OAuthCatalogValidationService(
    IProvIdenRepository provIdenRepo,
    IConfProvIdenRepository confProvIdenRepo)
```
- Elimina `PassPlatDbContext`, elimina `using Microsoft.EntityFrameworkCore`.
- `proveedores = repo.ObtenerTodosOrdenadosAsync().Value` (chequear `IsFailure` primero — PATRÓN AGENTS.md).
- `configs = repo.ObtenerTodosAsync().Value`.

### DI (AplicacionDependencyInjection.cs)
- **Sin cambios estructurales**: registros `AddScoped<IFederacionService, FederacionService>` (L141) e `IOAuthCatalogValidationService → OAuthCatalogValidationService` (L148) permanecen. Cambia solo la resolución interna de dependencias (hemeres solución DI existente de repos en `DatosDependencyInjection.cs:77-80`).
