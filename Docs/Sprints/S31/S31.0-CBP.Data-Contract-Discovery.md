## 7. Diseño — decisiones y recomendaciones por deuda

### DEUDA-005a — `GetRepository<TEntity>` (ambos lados)

**Recomendación final (decisión vinculante del usuario, 2026-08-15): RETAIN definitivo.** Se revierte la recomendación inicial de REMOVE.

Justificación de la decisión:
- El propósito de `GetRepository` es **deliberado y arquitectónico**: evita saturar constructores con inyección de dependencias y habilita aplicaciones **simples** (sin `AppRepository.cs` personalizados) a obtener repositorios directamente del UoW.
- "0 consumidores actuales" **no** equivale a "API innecesaria": la ausencia de consumidores se mide sobre productos complejos (PassPlat, InventaNet) que prefieren constructor injection, pero el framework debe seguir soportando apps simples.
- PassPlat es el consumidor **más complejo**; optimizar CBP únicamente para PassPlat destruiría el valor de conveniencia del framework.
- `GetRepository` delega en las factorías internas `IRepositoryFactoryAsync`/`IRepositoryFactorySync` (únicas que conocen `DbContext` para construir el repo); el mecanismo interno se conserva intacto.

**Documentación requerida (S31.1)**: marcar `GetRepository`/`GetCustomRepository` como "mecanismo de conveniencia del framework para aplicaciones simples; apps complejas optan por constructor injection y repos específicos".

### DEUDA-005b — `GetCustomRepository<TRepository>`

**Recomendación final (decisión vinculante del usuario, 2026-08-15): RETAIN definitivo en ambos lados (Sync y Async).**

- **Sync (A)**: InventaNet depende de ella funcionalmente (157 usos, repos custom heredan `IRepositorySync<T>`). Eliminarla sin migrar InventaNet primero produce break de compilación en todo InventaNet, y es un producto en producción.
- **Async (D)**: aunque no tiene consumidores conocidos, se conserva por **paridad** con Sync: eliminar Async manteniendo Sync crearía una asimetría explícita innecesaria. El criterio "0 consumidores" no justifica REMOVE cuando la contraparte Sync es superficie pública activa.

**Regla de parity**: el mismo mecanismo (obtener un repository custom desde el UoW) debe existir en ambos lados Async/Sync. RETAIN conjunto elimina el riesgo de asimetría accidental y mantiene la conveniencia del framework para apps simples.

### DEUDA-006 — `Query()` / `IQueryable`

**Recomendación: RETAIN definitivo (Async + Sync).** Es API pública legítima y está en uso productivo:
- Async: 19 consumidores funcionales en repositorios PassPlat (categoría A).
- Sync: 1 consumidor funcional en InventaNet (categoría A).

Preguntas del prompt respondidas:
- **¿`Query()` es API pública legítima?** Sí — es la vía de consulta declarada en `IReadRepositoryAsync/Sync` (parte del contrato compuesto `IRepository<T>`).
- **¿`CachingRepositoryDecorator` debe seguir existiendo?** No como parte de esta decisión; está **muerto** (categoría D). Un candidato a eliminación independiente (deuda accesoria de CBP.Data.Utilities), **fuera del alcance REMOVE de S31**, pero documentado aquí para su propia decisión.
- **¿`Specifications` es API soportada o legado?** Referenciada solo por tests (Architecture.Test). No tiene consumidores productivos en PassPlat ni InventaNet. Se recomienda **RETAIN** (es superficie pública del framework, referenciable) con registro explícito de "sin consumidores productivos conocidos" — no eliminarla por tests.
- **¿Consumidores externos fuera de PassPlat?** Sí — InventaNet (Query Sync, 1 uso + su ecosistema de repos Sync).
