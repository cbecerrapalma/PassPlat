## 3. Decisión de diseño B1/B2/B3 — RESUELTA POR EVIDENCIA → **B2**

### 3.1 Veredicto de la decisión abierta §15.1 (S32.0)

**B2 es la única opción que preserva el comportamiento observable actual**:

| Opción | Impacto sobre la fila `EmailQueue` | Verdicto |
|--------|-------------------------------------|----------|
| B1 (solo 5 jobs ejecutables) | Elimina la fila `EmailQueue` → el dashboard deja de mostrar `ItemsProcesados` (columna consumida en UI L290) | ❌ Regresión de datos no autorizada |
| **B2 (jobs + fuentes de estado operativo)** | Mantiene la fila con estado honesto (`Pending` real) | ✅ **Seleccionada** |
| B3 (contratos separados) | Dos contratos para una única tabla de consumo uniforme | ❌ Abstracción innecesaria sin consumidor diferenciado |

**Evidencia determinante**: `BackgroundStatusService.cs:58` (`ItemsProcesados = _queue.Pending`) es el **único** consumidor de `IEmailQueue.Pending` en el código, y alimenta una fila que la UI **ya muestra hoy** (`DashboardEnterprise.razor` L288–290). B2 no añade una abstracción "demasiado amplia" (preocupación original del usuario en §15.1): la incluye porque el dashboard **ya la expone end-to-end** desde S32.0. B1 alteraría el comportamiento observable sin aprobación.

### 3.2 Contrato definitivo

```csharp
// PassPlat.Aplicacion/Services/Dashboard/IBackgroundJobStatus.cs
public interface IBackgroundJobStatus
{
    string Nombre { get;                      }// comportamiento uniforme
```

### 3.4 `BackgroundStatusService` — reescritura funcional (sin reflexión)

```csharp
public sealed class BackgroundStatusService : IBackgroundStatusService
{
    private readonly IEnumerable<IBackgroundJobStatus> _jobs; // DI
    private readonly CBP.Logging.Interfaces.ILoggerService _olog;

    public Task<Result<List<BackgroundJobDto>>> GetBackgroundJobsAsync(CancellationToken ct = default)
    {
        var lista = new List<BackgroundJobDto>();
        foreach (var job in _jobs.OrderBy(j => j.Nombre))
        {
            var estado = (await job.ObtenerEstadoAsync(ct));
            var dto = ToDto(job.Nombre, estado);
            lista.Add(dto);
        }
        // fallback honesto por job:
        // Ejecutando==true → "Activo"
        // Ejecutando==false → "Detenido"
        // null → "No disponible" (NUNCA "Activo" falso)
    }
}
```

**Regla anti falso-positivo**: ninguna fila puede reportar `Activo`/`Detenido` sin estado verificado por la implementación. `null` → `"No disponible"`. Se elimina el `return true` incondicional de `IsServiceAlive`.

### 3.5 DTO — SIN CAMBIO DE FORMA

`BackgroundJobDto { Nombre; Estado; UltimaEjecucion; ItemsProcesados }` **se mantiene idéntico** (contrato HTTP estable; la UI no requiere migración). `BackgroundJobDto` sigue siendo el trasporte; `IBackgroundJobStatus` solo alimenta su construcción.

### 3.6 DI (S32.2)

- Registrar cada uno de los 5 jobs también como `IBackgroundJobStatus` (misma instancia singleton que el `AddHostedService` — mismo tipo de DI = misma instancia DCA).
- `EmailQueue` implementa `IBackgroundJobStatus`.
- `BackgroundStatusService` inyecta `IEnumerable<IBackgroundJobStatus>` (remueve acceso directo a `IEmailQueue` y a `IServiceProvider`).
