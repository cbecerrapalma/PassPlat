## 4. Desviaciones conocidas (documentadas, no bloqueantes)

### D-A: Pkcs 10.0.0 transitivo en CBP.Emails (no 10.0.10)
- **Observación**: `CBP.Emails` resuelve `System.Security.Cryptography.Pkcs 10.0.0` (transitivo desde MimeKit 4.17.0, que declara `[10.0.0,)`), no el 10.0.10 del catálogo.
- **Causa**: el pin central solo aplica a referencias **directas**; el pinning transitivo está deshabilitado (D2: proteger Protocols); MimeKit no exige techo superior.
- **Impacto**: nulo. 0 usos de Pkcs en código CBP (Validado S36.1 D3: 0 matches SignedCms/CmsSigner/EnvelopedCms/Oid). `CBP.Excel` sí resuelve Pkcs 10.0.10 (via Xml directo), donde Pkcs se usa.
- **Decisión**: aceptada como coherente con el diseño (D2/D5). No se añade PackageReference directo a CBP.Emails para no inflar un proyecto que no usa la API.

## 5. Regla de gobernanza confirmada

**El catálogo CPM es la fuente de versiones para referencias directas.** Cualquier nueva referencia directa resuelve desde `Directory.Packages.props` — y solo podrá añadirse si está en el catálogo (NU1008 lo garantiza en tiempo de restore). Ello convierte la gobernanza de versiones en **enforcement ejecutable**, análogo al guard Roslyn de S33.2.

Ningún paquete sin aprobación puede entrar sin una edición formal del catálogo (que es revisable en G0-backup / diff).
