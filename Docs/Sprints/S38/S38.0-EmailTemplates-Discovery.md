## 6. Hallazgos

### 6.1 H1 — El baseline S26 "17/22" no es reproducible

EmailLog actual = 34 filas (Ids 1-34, 2026-08-05 en adelante). El re-seed de la Fase 7.9 (SEED_VERSION 2.0.0) purgó los EmailLog históricos de S26 (Ids hasta 73). Cualquier "template certificado" del inventario S26 debe **re-considerarse con evidencia actual**: solo `new-ip` (16), `role-assigned` (17), `app-registered` (22) y `external-login` (27) tienen EmailLog `enviado` hoy.

### 6.2 H2 — `new-ip` está certificado por S21/S22, no por el fixture S26

Los 10 EmailLog de `new-ip` corresponden a los gates S21.4/S21.5/S21.6/S22 (Ids 23/25/26/27) + validaciones 2026-08-14. La cadena completa `Event_Published → Email_Queued → Event_Handled → Email_Sent` fue certificada en vivo con correlación W3C. **El AGENTS.md (S26-001) no lo reflejó**: quedó registrado como "pendiente, sin endpoint público". **Defecto de contenido**: el template usa `{{IP}}` / `{{FechaHora}}`, el handler manda `DireccionIP` / `FechaDeteccion` (FechaHora la aporta el motor). El email llega pero con la IP vacía.

### 6.3 H3 — Mismatch emisor↔template en 3 de 5

- `first-login` (12): template `{{AppName}}`; emisor (job + trigger) NO provee `AppName` → asunto "Primer inicio de sesión - " (vacío).
- `new-device` (15): template `{{Dispositivo}}/{{IP}}`; emisor `NombreDispositivo/IpAddress` → devcuerpo con campos vacíos.
- `new-ip` (16): template `{{IP}}`; emisor `DireccionIP` → cuerpo con IP vacía (el correo sí llega).
- `mfa-code` (3): en ruta job, faltan `ExpiraMinutos` (sí lo manda `SendMfaCodeAsync` directo).

**El motor Fluid no falla en placeholder ausente** (renderiza vacío): estos mismatches no rompen el envío, degradan el contenido. → candidato de fix S38.2 (alinear vars emisor↔template).

### 6.4 H4 — Disparadores disponibles

| Template | Disparador para certificación | Ruta |
|----------|------------------------------|------|
| `password-expired` | `POST /api/password/trigger-expiration` `[Authorize]` | manual + job 24h |
| `first-login` | `POST /api/password/trigger-first-login` `[Authorize]` | manual + PrimerUso |
| `mfa-code` | login con método MFA **Email** principal en usuario con email + requiere MFA | inline |
| `new-device` | login con `idDisp` no confiable | inline automático |
