## 3. Cambios aplicados

### 3.1 Sustantivo — `EmailQueue.cs:105-126`
```csharp
var correlationId = job.CorrelationId
    ?? _httpContextAccessor.HttpContext?.Items[LoggingPropertyNames.HttpCorrelationIdKey] as string
    ?? Guid.NewGuid().ToString("N");

await _channel.Writer.WriteAsync(job with { CorrelationId = correlationId }, ct);
// Email_Queued usa la misma correlationId
```
**Corrección fundamental**: antes el fallback existía solo para el log; el `job` escrito al channel conservaba su `CorrelationId` original (Guid local o null). Con `job with { CorrelationId }` la persistencia es completa.

## 6. Observaciones / limitaciones

1. **BUG-017.1.3 (re-aparece en esta sesión)**: endpoints `[Authorize]` (`/api/password/trigger-expiration`, `/api/usuarios`) devuelven 401 con `IDX10517` (`token's kid is missing`) en `CBP.Authentication.JwtBearer.JwtTokenService` incluso con token recién emitido por el mismo proceso. **Fuera del alcance S41** — no toca la cadena de correlación de emails (se certificó vía endpoints anónimos de login MFA). Registrado como incidente pendiente del framework de autenticación.
2. **Entorno**: la API se certificó en puerto 5259 (perfil `dotnet run`, ASPNETCORE_ENVIRONMENT=Development). Al ejecutar el EXE directo en producción el redirect HTTPS 307 reintroduce el problema BUG-017.1.3 (comportamiento conocido).
3. **E2E background sin HttpContext (G5)**: no se pudo forzar una campaña real de `PasswordExpirationBackgroundService` (0 usuarios vencidos en DB); el fallback local sin HttpContext queda cubierto por el test unitario G3 #1 (`Enqueue_SinHttpContext_JobPersisteCorrelationIdLocalNoNull`) de forma determinista.
