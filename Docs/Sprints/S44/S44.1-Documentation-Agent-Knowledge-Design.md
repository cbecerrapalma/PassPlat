## Purpose and non-goals

This design converts the S44.0 physical audit into a reversible migration plan. It defines classification, responsibility, source-of-truth, link handling, batch gates, rollback and acceptance criteria. It does **not** create a target tree, rewrite `AGENTS.md`, repair references, move/rename/delete files or alter code/configuration.

## Design inputs and resolved reference analysis

S44.0 resolved 38 Markdown destinations and found 0 broken. This phase also inspected 350 inline-backtick path-like references. 72 fail a literal filesystem resolution, but they must not all be called broken: 36 are patterns, glob examples, grouped paths or directories (`SXX`, `*`, `{...}`, `..`, `/`); 16 are intentionally historical paths inside the archive; and 20 are actionable textual-reference candidates.

| `AGENTS.md` | Permanent invariants and router | Always load; no historical detail | Root agent instructions |

`Docs/audit/` is classified as immutable visual evidence. Its eventual relocation to `Evidence/Visual/` is a **separate, high-risk batch** and is excluded from the first implementation authorization unless the user explicitly approves it after its inbound-reference and hash manifest is reviewed.

## AgentsIA taxonomy and document contract

The S44.2 target will create only the following documented operational files; a file may be deferred when no distinct actionable content can be sourced without duplication:

1. Foundation: `README`, `Architecture`, `Contracts`, `Development`, `Testing`, `Operations`.
2. Product domains: `Domain`, `Data`, `Database`, `Security`, `Authentication`, `Authorization`, `MultiTenant`, `Email`, `OAuth`, `Events`, `Logging`, `Observability`, `Caching`, `BackgroundJobs`, `Outbox`, `UI`, `WebAPI`, `Configuration`.
3. Framework: `Framework/README`, `CBP`, `CBPData`, `CBPEvents`, `CBPLogging`, `CBPAuthentication`, `CBPCaching`, `CBPSecurity`.
4. Navigation: `Navigation/Sprints`, `PermanentDocs`, `Evidence`, `Troubleshooting`.

Each created file is capped by purpose, not duplicated specification. Its mandatory headings are `Purpose`, `Scope`, `Mandatory Rules`, `Patterns`, `Anti-Patterns`, `Canonical Contracts`, `Relevant Projects`, `Load Next`, `Do Not Load`, and `Historical References`. It links to, but never copies, `Framework`, sprint or evidence content.

`Database`, `OAuth`, and `Framework` are explicitly excluded from UI work unless that task changes their boundary. `Sprints/ARCHIVE` is excluded from every default load set.

## Source-of-truth decision matrix

| Content family | Canonical source after migration | Non-canonical handling |
|---|---|---|
| Framework logging/data/result contracts | `Docs/Framework/*` | AgentsIA links only |
| Current architecture decisions | ADRs and selected current `Architecture` documents | Historical reports link/archive only |
| Schema/persistence conventions | `D:\CODIGOS\BBDD\PASSWORDS*.sql` + `Docs/Database` explanatory index | AGENTS/AgentsIA concise pointers only |
| Implementation conventions | Domain/Data/Application/UI reference docs | AGENTS invariant summary + AgentsIA route |
| Sprint decisions/evidence | `Docs/Sprints/SXX/*` | Archive is non-authoritative summary |
| Technical evidence | `Docs/Evidence/*` and protected `Docs/audit/*` | Link only; never rewrite the asset |
| Current operational instruction | `AGENTS.md` + selected AgentsIA file | No duplicate in sprint reports |

The 113 `REQUIRES-DESIGN` documents are not bulk-migrated. S44.2 must add a manifest row for each one: path, owner, status (`CURRENT`, `HISTORICAL`, `RESOLVED`, `STALE`, `ARCHIVED`, `INFORMATIONAL`), classification (`KEEP`, `MERGE`, `REFERENCE`, `ARCHIVE`, `REMOVE`, `REQUIRES-DESIGN`), canonical successor, inbound count, and action. `REMOVE` is prohibited unless the row has no inbound links, a successor/retention rationale and explicit batch approval.

## S44.2 execution design

### Preconditions

1. Create `Docs/Sprints/S44/S44.2-Documentation-Agent-Knowledge-Implementation-Certification.md` as the batch manifest and decision log.
2. Produce SHA-256 manifests for `AGENTS.md` and every `Docs/` file before mutation; copy them to an out-of-tree timestamped backup location approved by the user. Git cannot provide rollback here.
3. Run the final reference resolver before every batch. It must distinguish Markdown, exact backtick path, directory/glob/template syntax, historical prose and external paths.
4. Record source-tree file extension hashes before and after every batch. Any `.cs`, `.sql`, `.csproj`, `.slnx`, `.json` or `.razor` delta is a STOP unless separately authorized.

### Ordered batches

| Batch | Scope | Mutations permitted after S44.2 approval | Gate focus |
|---|---|---|---|
| B0 | Backup + manifests + resolver evidence | No content migration | Restore rehearsal / hash baseline |
| B1 | Add AgentsIA navigation and foundation documents | Create operational files and links only | No contract duplication; router paths resolve |
| B2 | Add domain AgentsIA files | Create selected domain routers | Load/Do-Not-Load and source links verified |
| B3 | Replace AGENTS with compact router | One atomic replacement after B1/B2 validation | <750 lines; no historical registry; all mandatory invariants preserved |
| B4 | Update active references / indexes | Fix only active exact destinations and root README | Full inbound/outbound graph and direct links pass |
| B5 | Classify and archive approved legacy documents | Only manifest-approved documents; no Evidence/Framework | Fan-in zero or references rewritten first |
| B6 | Optional evidence consolidation | Excluded by default | Explicit approval, hashes and visual inventory required |

Each batch runs filesystem validation, full link/reference classification, duplicate/stale scan, source-file no-change check, `dotnet build PassPlat.slnx`, PassPlat tests, CBP build/tests when Framework references change, and then records PASS/FAIL. A failure stops the sprint; later batches do not start.

## Rollback design

Rollback is file-granular and independent of Git. B0 supplies `before.sha256`, `after.sha256`, file action manifest, and an immutable physical backup. A batch failure restores only its listed changed files, validates the restored SHA-256 values and reruns the applicable graph/build/test gates. No delete is permanent until the final S44.3 gate passes; moves are performed as copy-then-verify-then-remove only after inbound references resolve.
