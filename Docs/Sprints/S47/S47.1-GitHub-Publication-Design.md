## 3. Estrategia

**Único comando autorizado en S47.2:**

```
git push -u origin master
```

**NO usar:** `--force`, `-f`, `--force-with-lease`, `--mirror`, `pull --rebase`, `merge`, `reset`, `init`, `remote add`, `push --mirror`, `--allow-unrelated-histories`.

**Por qué:** Historias relacionadas y `fast-forwardable` (`remote show origin`); `README` remoto es padre de `inicio`, no hay divergencia ni commit remoto desconocido (MCP `github_list_commits` → 1 commit `8fccfd6`). `push` publicará `9e800ef` como `origin/master` sin reescribir historia.

**Preflight S47.2 (repetir):**
- `git status --short` → vacío (clean)
- `git branch --show-current` → `master`
- `git rev-parse HEAD` → `9e800ef8d1c1683a408fbe8f55cbd9a10321e084`
- `git rev-parse origin/master` → `8fccfd6ba18f1e19d8cb2d2ec6959f0d2effe396`
- Si alguno difiere → **STOP**.

13. operación destructiva necesaria

## 7. Rollback

Si `git push -u origin master` falla:

1. **NO** `force push`
2. Capturar `stderr` (`! [rejected]`)
3. `git fetch origin` + `git log --oneline --graph --all -n 10` + `git remote show origin`
4. Si apareció `9e800ef` remoto desconocido → volver a `S47.1`
5. Restaurar `origin` si cambió: `git remote set-url origin https://github.com/cbecerrapalma/PassPlat.git` (solo si D1 falla)

Rollback de commit local **no necesario** — `push` no altera `HEAD` si falla.
